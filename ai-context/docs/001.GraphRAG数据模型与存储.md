# GraphRAG 数据模型与存储

> 详解 GraphRAG 索引阶段生成的所有数据表、字段含义、Embedding 内容，以及数据间的关联关系。
>
> 源码路径：`packages/graphrag/graphrag/data_model/`

---

## 1. 存储概览

GraphRAG 索引完成后输出一组 **Parquet 文件**（列式存储），每个文件对应一张数据表：

```
output/
├── documents.parquet          # 原始文档
├── text_units.parquet         # 文本块
├── entities.parquet           # 实体
├── relationships.parquet      # 关系
├── communities.parquet        # 社区（Leiden 聚类结果）
├── community_reports.parquet  # 社区摘要报告
└── covariates.parquet         # 协变量/声明（可选）
```

这些 Parquet 文件在查询时被加载到内存中，作为各搜索模式的数据源。

## 2. 各数据表详细结构

### 2.1 TextUnit（文本块）

源码：`data_model/text_unit.py`

```python
@dataclass
class TextUnit(Identified):
    text: str                              # 文本内容
    entity_ids: list[str] | None           # 该文本块中抽取出的实体 ID
    relationship_ids: list[str] | None     # 该文本块中抽取出的关系 ID
    covariate_ids: dict[str, list[str]] | None  # 相关协变量
    n_tokens: int | None                   # token 数
    document_id: str | None                # 来源文档 ID
    attributes: dict[str, Any] | None      # 扩展属性
```

**生成方式**：程序将原始文档按 token 数切分（默认 ~300 token/块），每块生成唯一 ID = `sha512(text)`。

**Parquet 示例**：

| id | document_id | text | n_tokens | entity_ids | relationship_ids |
|----|-------------|------|----------|------------|-----------------|
| abc123 | doc-001 | "战斗系统是游戏的核心..." | 287 | ["ent-01", "ent-02"] | ["rel-01", "rel-02"] |

### 2.2 Entity（实体）

源码：`data_model/entity.py`

```python
@dataclass
class Entity(Named):
    # 继承自 Named: id, short_id, title
    type: str | None                       # 实体类型（PERSON, ORG, CONCEPT...）
    description: str | None                # LLM 生成的实体描述
    description_embedding: list[float] | None  # description 的向量 ← 被存入向量库
    name_embedding: list[float] | None     # 实体名的向量（可选）
    community_ids: list[str] | None        # 所属社区 ID 列表
    text_unit_ids: list[str] | None        # 出现在哪些文本块
    rank: int | None                       # 重要性排名（= degree 度数）
    attributes: dict[str, Any] | None      # 扩展属性
```

**Embedding 的内容**：

```
被 embed 的是 entity 的 description（描述文本）
存入向量库后，用于 Local Search 的语义匹配

示例：
  title = "战斗系统"
  description = "游戏的核心玩法模块，负责伤害计算和战斗流程管理"
  description_embedding = embed("游戏的核心玩法模块，负责伤害计算和战斗流程管理")
```

**关键区别 vs LightRAG**：
- LightRAG 的 entity embedding = `entity_name + "\n" + description`
- GraphRAG 的 entity embedding = **仅 description**（不拼接 entity_name）

**rank 字段**：等于该实体在图中的 degree（连接边数），度数越高越重要。

### 2.3 Relationship（关系）

源码：`data_model/relationship.py`

```python
@dataclass
class Relationship(Identified):
    # 继承自 Identified: id, short_id
    source: str                            # 源实体名称
    target: str                            # 目标实体名称
    weight: float | None = 1.0             # 边权重（合并次数）
    description: str | None                # LLM 生成的关系描述
    description_embedding: list[float] | None  # 关系描述的向量（可选）
    text_unit_ids: list[str] | None        # 出现在哪些文本块
    rank: int | None = 1                   # 重要性排名
    attributes: dict[str, Any] | None      # 扩展属性
```

**关键区别 vs LightRAG**：
- LightRAG 的关系包含 `keywords` 字段 → 用于 relationships_vdb 的语义匹配
- GraphRAG 的关系 **没有 keywords** → 不通过向量检索关系，而是通过图遍历获取

**weight 的含义**：同一对实体在不同 TextUnit 中被多次抽取到关系时，weight 累加。用于 Leiden 聚类和结果排序。

### 2.4 Community（社区）

源码：`data_model/community.py`

```python
@dataclass
class Community(Named):
    # 继承自 Named: id, short_id, title
    level: str                             # 层级（"0"=叶子, "1"=中间, "2"=根...）
    parent: str                            # 父社区 ID
    children: list[str]                    # 子社区 ID 列表
    entity_ids: list[str] | None           # 成员实体 ID
    relationship_ids: list[str] | None     # 社区内关系 ID
    text_unit_ids: list[str] | None        # 关联文本块
    covariate_ids: dict[str, list[str]] | None  # 关联协变量
    size: int | None                       # 大小（文本块数）
    period: str | None                     # 时间分期（可选）
    attributes: dict[str, Any] | None      # 扩展属性
```

**生成方式**：Leiden 算法（纯程序，零 LLM 成本）对知识图谱做层级聚类，输出社区划分。

### 2.5 CommunityReport（社区摘要报告）

源码：`data_model/community_report.py`

```python
@dataclass
class CommunityReport(Named):
    # 继承自 Named: id, short_id, title
    community_id: str                      # 关联的社区 ID
    summary: str                           # 摘要（短版）
    full_content: str                      # 完整报告内容
    rank: float | None = 1.0               # 重要性评分（LLM 给出，1-10）
    full_content_embedding: list[float] | None  # 报告内容的向量 ← 用于 Global Search
    size: int | None                       # 大小
    period: str | None                     # 时间分期
    attributes: dict[str, Any] | None      # 扩展属性
```

**Embedding 的内容**：

```
被 embed 的是 full_content（完整报告文本）

示例：
  title = "战斗与技能系统"
  summary = "该社区涵盖游戏的核心战斗玩法..."
  full_content = "# 战斗与技能系统\n\n## Summary\n该社区涵盖...\n\n## Key Entities\n..."
  full_content_embedding = embed(full_content)
```

**report 的结构**（LLM 生成）：

```
# {Title}

## Summary
{executive overview}

## Key Entities
- {entity_1}: {role description}
- {entity_2}: {role description}

## Findings
1. {finding_1} [Data: Entities (id1, id2)]
2. {finding_2} [Data: Relationships (id3, id4)]

## Rating
{importance_score}/10
```

## 3. 数据间的关联关系

```
Document ─────1:N─────→ TextUnit
                            │
                     ┌──────┼──────┐
                     │      │      │
                     ▼      ▼      ▼
                  Entity  Relationship  Covariate
                     │      │
                     │      │ (weight = 合并次数)
                     │      │
                     ▼      ▼
              ┌─── 知识图谱 (NetworkX) ───┐
              │   nodes = entities        │
              │   edges = relationships    │
              └───────────┬───────────────┘
                          │
                          ▼ Leiden 聚类
                      Community
                          │
                          ▼ LLM 摘要
                    CommunityReport
```

**双向引用**：

| 从 | 到 | 通过字段 |
|----|----|---------| 
| TextUnit → Entity | `text_unit.entity_ids` |
| TextUnit → Relationship | `text_unit.relationship_ids` |
| Entity → TextUnit | `entity.text_unit_ids` |
| Entity → Community | `entity.community_ids` |
| Relationship → TextUnit | `relationship.text_unit_ids` |
| Community → Entity | `community.entity_ids` |
| Community → Relationship | `community.relationship_ids` |
| Community → TextUnit | `community.text_unit_ids` |
| CommunityReport → Community | `report.community_id` |

## 4. 向量库中存了什么

GraphRAG 使用向量库存储 **Entity 的 description embedding**，用于 Local Search 的语义匹配：

```python
# 向量库中每条记录
{
    "id": "ent-abc123",              # Entity ID
    "vector": [0.012, -0.034, ...],  # embed(entity.description)
    "attributes": {
        "title": "战斗系统",          # 用于反查实体
    }
}
```

**查询时**：

```
用户查询 → embed(query) → 向量库 similarity_search → top-k Entity IDs
                                                          │
                                                          ▼
                                               从 Parquet 加载完整实体数据
```

**注意**：GraphRAG 的 CommunityReport 的 `full_content_embedding` 虽然也存在，但 Global Search **不使用向量检索**来找社区报告——它直接读取指定 level 的所有报告。这个 embedding 主要用于 DRIFT Search 的初始阶段。

## 5. 与 LightRAG 存储的对比

| | GraphRAG | LightRAG |
|--|----------|----------|
| **存储格式** | Parquet 文件（列式） | 向量库 + 图数据库 |
| **Entity embedding 内容** | description（仅描述） | entity_name + "\n" + description |
| **Relationship embedding** | 可选（description_embedding）| keywords + "\t" + src + "\n" + tgt + "\n" + description |
| **向量检索用途** | Local Search 找实体 | Local: 找实体；Global: 找关系 |
| **社区/宏观查询** | 读取社区摘要报告（非向量检索） | 向量检索 relationships_vdb |
| **关系获取方式** | 图遍历（找到实体后获取邻接关系） | 向量检索 + 图遍历 |
| **关键词字段** | 无 | ✅ 关系有 keywords，用于宏观匹配 |
| **层级结构** | ✅ 社区层级树（Leiden） | 无显式层级 |
